## Context that changes how you work here

This is a **4-hour hackathon build judged by a live demo**, not a product. Optimize for demo impact, not maintainability. Speed and visible polish beat correctness at the margins.

- **If it isn't in the 90-second demo, don't build it.** See `scope-60`
- **Deploy early and continuously.** Not at the end. See `ship-it`
- **No auth, no settings, no responsive work** unless the demo shows it
- Ugly-but-working beats elegant-but-unfinished

## Architecture

Next.js 16 App Router, React 19, Tailwind v4, TypeScript. No `src/`; `@/*` maps to the repo root.

| Path | Role |
|---|---|
| `app/page.tsx` | Client component; `useChat` from `@ai-sdk/react` drives the UI |
| `app/api/chat/route.ts` | **The only place the Anthropic key is used.** `streamText` → `toUIMessageStreamResponse()` |
| `lib/supabase.ts` | Browser client, anon key only |
| `components/ShareOverlay.tsx` | Demo QR screen (press `Q`). Live URL read from `window.location`, so it is right wherever deployed |
| `.claude/skills/` | 17 hackathon skills |

Flow: client `useChat` → `POST /api/chat` → `streamText` against Claude → streamed back. Keep it that way; the key must never reach the browser.

**Not yet deployed.** The Vercel import at vercel.com/new is a manual browser step. Until it's done there is no live URL, and the QR overlay will point at `localhost`. See `ship-it`.

### AI SDK v7 gotchas

This is **AI SDK v7** and differs from v5 patterns in training data:

- **`convertToModelMessages` is async** — `await` it or the build fails with a `Promise<ModelMessage[]>` type error
- Response helper is `result.toUIMessageStreamResponse()`
- `useChat` gives `sendMessage({ text })` and `status` — not the older `input`/`handleSubmit` bundle. Hold input in your own `useState`
- Message content is `m.parts[]`, not `m.content`

Next.js 16 likewise has breaking changes from training data. `AGENTS.md` is regenerated by `next dev` and says to read `node_modules/next/dist/docs/` before writing framework code — do that rather than guessing.

## Skills, not subagents

Use the persona **skills** above — not the Agent tool. A skill loads expertise into *this* session with full context; a subagent starts cold, costs latency, and can't see the conversation. On a 4-hour clock the bottleneck is KD's build throughput, and agents don't make code land faster.

**One exception:** parallel research during the 9:10–9:25 block, when several challenges need evaluating under a hard 15-minute cap. Fan out there; nowhere else.

HA's separate session is already the team's parallelism, and it's better than a subagent because a human steers it.

## Data

Halifax open data is **verified and catalogued** in `halifax-data` — 339 public queryable layers, no auth, CORS open (query it straight from the browser; no proxy route needed). Do not query it live on the demo path; seed it (`demo-safe`).


**Attribution is required.** HRM data is under the [HRM Open Data Licence](https://data-hrm.hub.arcgis.com/pages/open-data-licence); the credit line in `README.md` must stay if that data ships.

## Secrets

`ANTHROPIC_API_KEY` and `SUPABASE_SERVICE_ROLE_KEY` are **server-only** — never `NEXT_PUBLIC_`. Claude calls go through a server route.

**The repo is public**, so a committed key is exposed the moment it's pushed, not at release. Deleting the commit does not undo it — rotate the key instead. The project will be open-sourced after the event; the release checklist is at the end of `PROCESS.md`.
